# 本地多智能体原型

这是早期角色实验的历史说明。当前统一启动入口为工作区根目录 `启动工作台.cmd`；早期实验保留在“经营分析”的折叠区，原定四角色在“协作工作台”中运行。

## 使用

双击工作区根目录的 `打开智策物流助手_学校模型.cmd`，输入北理工模型密钥；打开页面后选择完整月份，商家选择“全部”，可选类别，再在第⑥部分点击“运行多智能体分析”。服务向模型发送筛选条件、最多5个商家的延迟订单数、有效样本数和多商家订单数；实际建议需要人工确认。页面可以展开复核SQL与完整结果。每次调用三次模型，需网络及模型服务可用。

## 分工与协作

1. 数据角色：以程序和两条独立SQL完成订单级统计、商家筛选和复核，按历史延迟订单量等规则挑选最多5家；这是确定性数据工具，不调用大模型。
2. 诊断角色：读取汇总数据，从预设的交运、承运、地址三类方向中选择需要核查的方向；这些是待核实假设，不是事实或归因。
3. 建议角色：读取汇总和诊断，选择预设的人工核对行动，不自动联系商家。
4. 审核角色：读取上游摘要并给出通过或拒绝。程序另行校验各模型输出的JSON格式和允许值，审核拒绝时页面不展示建议正文；任意步骤异常则请求失败，不作为成功输出。模型审核不是对业务事实的独立证明。

角色使用同一个模型的独立请求和不同系统提示词，按顺序传递结构化结果。当前输出刻意限制在预设选项，便于审查，但不等同于自主开放式分析，也没有接入华为云AgentArts或实际物流系统。

## 验证及限制

2026-11-01 用真实数据库和北理工 `deepseek-v4-flash` 完成一例 `2018-01` 全类别的三次真实模型调用；数据、诊断、建议、审核四个阶段均完成，结果见 `reports/多智能体真实调用样例.json`。浏览器也用相同月份执行了一次完整流程并显示结果。47项自动测试通过，包括模拟模型输出异常、审核拒绝和无候选商家时的处理；模拟测试不能代表真实模型准确率。2018年历史数据不能说明实时风险、延迟原因、商家责任或干预收益。需要更多月份、类别、异常场景与人工评审才能评价稳定性和业务效果。
