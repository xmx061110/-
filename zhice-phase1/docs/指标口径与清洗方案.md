# 指标口径与清洗方案（v1.0.0）

## 数据粒度与处理顺序

1. 完整保留九个原始 CSV，记录文件名、大小、SHA-256、ZIP CRC 和来源。不修改原始文件。
2. 每张表按字符串读取，只有空字段视为缺失；邮编、订单、商品、商家标识保留字符串。
3. 全表完全相同的记录只在清洗层去重；主键冲突不任意保留一条，直接中止构建，要求审查。订单商品键为 `(order_id, order_item_id)`，付款键为 `(order_id, payment_sequential)`。
4. 日期按 `%Y-%m-%d %H:%M:%S` 解析。无效非空日期转缺失并写异常清单；下单时间缺失或无效则中止构建。保留原时间，不人为换算为 UTC。
5. 商品价、收取运费、付款额使用 Decimal 转整数分；关键金额缺失、负数、非法值或不能精确转分时中止构建。原金额文本仍保留。
6. 其他数量字段显式转整数，无法解析或非整数保留缺失；属性缺失不使用均值填充。纬度经度允许负数，检查合法数值范围；地理点按邮编聚合后才可关联。
7. 在独立的商品、付款、评价粒度上处理后，构造一单一行事实表；检查每个订单唯一及总金额守恒。

## 缺失与异常的具体处理

| 问题 | 实施规则 | 对结果的影响 |
|---|---|---|
| 取消 / unavailable | 保留订单，销售额排除；分别提供状态计数 | 总订单量可审查，不把失败订单当收入 |
| 未送达状态 | 不计入已送达销售额与送达延迟分母 | 属于历史快照，非最终失败 |
| 无商品订单 | 总订单量保留，商品金额为 NULL，商品行数 0 | 无法分配到类别或商家 |
| 无付款订单 | 付款 NULL，不填零；计数单列 | 商品成交额仍可由真实商品价计算 |
| 完全相同付款重复行 | 在清洗层移除完全重复行；记录审查统计 | 保留 raw 以追溯 |
| 相同付款组合键、内容冲突 | 中止构建 | 不任意删除可能真实支付 |
| 同订单多种支付或同金额多笔支付 | 保留并按订单合计 | 不以 order_id、金额或支付方式去重 |
| 分期 | payment_value 已是记录总额，不乘期数 | 避免把支付额放大 |
| 付款与商品加运费不平 | 差额绝对值 >1分进入异常清单；两种口径分别保留 | 不臆测退款、补贴和手续费 |
| 同订单多评价 | 保留全部；事实层选择最新有效评分 | 一单只贡献一次评价指标 |
| 缺少评价文本 | 保留 NULL；有有效评分仍可进入评分指标 | 不推断情绪 |
| 缺少评分 | 不进入低评分分母 | 不当作好评或低评 |
| 缺少商品类别 | 查询时归入 `__unknown__` | 金额不丢失 |
| 翻译表缺少类别 | 保留原葡语类别，不删除商品 | 不与类别缺失混同 |
| 日期先后矛盾 | 原始值保留，输出订单异常清单；按具体指标排除 | 无法比较的样本不当作准时 |
| 真实成本缺失 | profit_cents / profit_brl 均 NULL | 不编造成本或利润 |

### 多评价选择规则

只在评分为 1–5 的记录中，按填写时间、创建时间、review_id、全字段 SHA-256 依次升序，取每订单最后一条。缺失排序时间放在有效时间之前。哈希以原字段顺序的规范化字段值 JSON 编码计算，避免同时间记录受输入行顺序影响。保留选择记录的 `_source_row` 方便回溯。

该规则适合回顾性分析，不适合作为历史某一时点的预测特征。后续预测或 Agent 决策回测需增加 `as_of` 截止时间并重新设计可用信息规则。

## 五类指标

| 指标 | 定义 / 分母 | 空值及过滤行为 |
|---|---|---|
| 订单量 `order_count` | 筛选范围内全部状态的不同 order_id 数 | 无命中返回空列表；无商品订单仅存在总体/月份查询中 |
| 销售额 `sales_gmv_cents` | status=delivered 的命中商品 price_cents 合计 | 不含运费，非净收入；按类别/商家金额可加总 |
| 配送延迟率 `delivery_late_rate` | 延迟订单 / 有可比实际与预计日期的已送达订单 | 实际日 > 预计日为延迟，同一天不延迟；无有效分母为 NULL |
| 低评分占比 `low_score_rate` | 最新有效评分为1或2的已送达订单 / 有有效评分的已送达订单 | 未评价不入分母；无评分分母为 NULL |
| 商家履约 | 分商家订单、已送达快照占比、GMV、相关订单送达延迟、评分、单商家晚交运代理 | 共同订单结果不等于商家责任；必须看分母与多商家覆盖 |

### 延迟分母

要求订单状态 delivered，且下单、实际送达、预计送达时间有效；实际与预计不早于下单；如存在交运时间，实际送达不得早于交运。不满足的订单单独计数。交运早于下单本身不改变实际日与预计日的可比性，因此单独标注，但不因此排除送达延迟指标。

预计送达字段通常为当天零点，不能以完整时间直接判晚，否则当天晚上送达会被错算为延迟。这里对两个时间都取日历日后比较，不计算工作日，也不引入巴西节假日推断。

### 商家交运代理

只对一个订单仅有一家商家、状态非 canceled/unavailable、有交运时间、有最早商品发货截止、交运与截止均不早于下单的样本计算：订单级交运时间 > 该订单最早商品发货截止时间。

使用最早截止是保守的整单检查规则。由于没有每条商品和每家商家的独立交运轨迹，结果标明为代理率。多商家订单仍保留在商家订单、GMV 和相关订单延迟中，但不进入该代理率。`delivered_status_share` 只表示快照状态占比，不是最终履约成功率。

### 按月份、类别、商家筛选

月份取下单时间 `YYYY-MM`。类别使用葡语代码，商家使用 seller_id。多个筛选条件在同一商品明细行上取交集，商品金额只汇总命中明细；评价和配送结果仍为该订单的整单结果。

当订单跨类别或跨商家时，它会出现在多个分组中，因此订单量、评分人数、延迟人数、比率不可直接加总。商品成交额和运费按真实商品归属，可跨类别或商家加总。整单付款不能可靠拆到类别/商家，本项目直接返回 NULL，不按比例虚构分摊。

所有比率字段均为 0–1 的比例，并同时提供分子分母。没有有效分母返回 NULL。商家 `--min-orders` 仅设订单样本数门槛，没有自动开展假设检验或因果分析。

## 后续接口扩展

```python
from pathlib import Path
from zhice.metrics import get_metrics

rows = get_metrics(
    Path('data/warehouse.sqlite'),
    month='2018-01', category='beleza_saude', seller=None,
    group_by='month', min_orders=0,
)
```

参数经过校验并绑定到 SQL，不执行任意模型生成 SQL。接口只读打开数据库，返回 JSON 可序列化结构。后续可在外层增加 AgentArts 工具适配、鉴权、日志、时间截止策略和业务阈值；当前不启动网络服务。
