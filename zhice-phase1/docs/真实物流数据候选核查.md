# 真实物流数据候选核查

核查日期：2026-11-02。LaDe固定版本20个原始文件已完整下载、验证，并完成独立SQLite导入和真实揽收事件接入，见 [数据库与算法接入报告](LaDe数据库与算法接入报告.md)。Amazon仍仅核查说明。

## 优先候选：菜鸟LaDe

- 发布方托管：[Cainiao-AI/LaDe](https://huggingface.co/datasets/Cainiao-AI/LaDe)。本次API返回200，数据仓库公开且未设置登录门槛；代码地址以发布方说明中的 `https://github.com/wenhaomin/LaDe` 为准。
- 发布方介绍约1067.7万包裹、约2.1万快递员、6个月运营记录，覆盖上海、杭州、重庆、吉林、烟台。
- LaDe-P是揽收场景，包含 `package_id`、`courier_id`、`time_window_start/end`、`accept_time`、`pickup_time` 及对应事件位置字段。可以基于真实接单和完成时间构造历史事件回放；对时间窗有效的样本可定义揽收超窗指标。
- LaDe-D是派送场景，包含接单、送达时间及位置。当前字段说明未列出派送承诺截止时间，不能直接把它当作带真实延迟标签的数据。
- 数据仓库还列出了路网和20秒轨迹相关文件；轨迹格式与坐标语义尚未实测，不直接套用真实经纬度距离计算。
- 适合把项目切口落到“末端揽收超时预警与任务优先级调整”。这是末端物流数据，不能称干线快运数据或当前实时生产接口。
- 已核查的字段中没有真实加急费用、改派费用、催单行动记录或干预后的对照结果，不能替换全部模拟输入。

原始字段说明保存于 `reports/real-data-research/LaDe_README.md`。数据卡标示Apache-2.0，正文还提到研究用途；完整下载前应继续核对发布方条款，当前不对商业使用作法律判断。

## 备选：Amazon历史末端路线数据

- [AWS官方目录](https://registry.opendata.aws/amazon-last-mile-challenges/)核实为9184条历史路线，来自2018年美国5个都市区域，包含路线、站点、包裹数据；官方目录提供无需AWS账号的公开S3读取方式。
- [官方文档](https://github.com/MIT-CAVE/rc-cli/blob/main/templates/data_structures.md)列出真实执行顺序、包裹扫描状态、配送时间窗、车辆容积容量及站点间行驶时间。
- 行驶时间是历史实现时间的平均值，不是当前实时交通，也不能充当每次实际到达的完整时间线；部分包裹没有时间窗。
- 适合后续路线顺序、容量约束和配送尝试状态分析；不是现有预算干预模型的直接替代数据。
- 官方目录标示CC BY-NC 4.0。当前仅核实文档与公开入口，尚未下载或解析数据文件。

字段文档保存于 `reports/real-data-research/Amazon_data_structures.md`。

## 建议接入顺序

先单独试导LaDe-P的一个城市，验证时间窗完整性、日期格式、重复包裹、接单/完成顺序以及可用样本规模，再建立真实历史回放。回放时只有走到相应事件时间才允许读取完成事实，不能提前使用未来完成时间预测当前风险。

保留Olist的经营分析作为已有成果。两份数据没有共同订单关联关系，不将LaDe与Olist强行合并成同一企业业务流水。历史状态可以真实，新的调度动作和其效果仍需模拟或另外取得真实行动记录；无法仅靠历史轨迹证明干预减少了延误。
