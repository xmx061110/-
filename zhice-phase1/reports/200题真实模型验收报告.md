# 本地单智能体200题真实模型验收

日期：2026-11-01。模型：北理工 BIT MaaS `deepseek-v4-flash`。本次每轮均实际请求200次模型接口，未用模拟响应代替真实调用。模型返回后由应用检查查询范围与参数，因此通过数是“模型加程序约束”的系统结果，不是纯模型能力分数。

每个目录均包含 questions.json、responses.jsonl 和 results.json：完整题目、期望条件、实际系统决策、逐题通过标记、耗时与数据库 SQL 证据均保留。responses.jsonl 在数据库对照之前记录模型解析阶段，最终结论以 results.json 为准。运行脚本为 `work/evaluate_200.py`。

题集由固定模板生成，有200条不同文本，但部分只改写开头或替换月份、代码，语义场景远少于200种。120条可查询题覆盖月份、类别、商家、两项组合、三项组合；80条限制题覆盖相对时间、缺失信息、非法条件、比较、排行、趋势、预测、利润、真实成本、原因、额外筛选、多类别、日范围、操作请求和编造请求。题集用于开发与修复，不是独立盲测或真实用户样本。

## 修复及效果

1. 日范围不能扩大成整月：在模型返回后检测日期精度，不支持时明确提示。
2. 多工具调用、无效JSON、非法参数或额外字段不再作为可执行查询输出，而是返回限制提示。
3. 明确已支持低评分占比、取消订单数等指标，区别于按某个评分或状态额外筛选；中间轮过度拒绝的退步完整保留。
4. 相对时间不能猜历史月份，类别及商家代码必须由用户明确提供。
5. 操作数据和编造数据请求不再误映射为普通统计查询。

最终轮可查询题118/120，限制题80/80。剩余两题是 `Q047` 与 `Q049`：分别询问 `informatica_acessorios` 和 `moveis_decoracao` 的延迟率，被模型保守拒绝。该局限仍存在，可直接通过页面选择类别查询；本报告不将拒绝算作正确回答。

成功的查询按实际提取条件执行SQLite计算与raw_*原始表复核，每组条件比对21项指标。最终轮覆盖65组不同条件，共1365项SQL对照全部一致。同条件问题共用确定性查询证据，每题通过evidence_key引用；不把复用证据误计成独立数据库样本。完整SQL可从结果文件复制复算。本次43项项目回归测试全部通过，包含本机HTTP接口及新排查工具。

本次测试只能说明该固定开发集上的行为；同一服务也可能随时间或采样产生不同输出。人工确认筛选条件仍是界面流程的一部分。历史数据不能支持实时物流、真实成本、归责或干预收益。

## 已推进的后续功能

新增“历史配送延迟排查”工具、`POST /api/triage` 接口与本地页面第⑤部分。2018-01示例核对970家商家的全部指标，39家达到至少30笔有效配送且有延迟的门槛，展示前10家。排序先按延迟单量，再按延迟率；建议是核查记录，不自动归责或联系商家。

已实际通过浏览器选择2018-01并点击生成按钮，页面显示上述清单。详细口径和复现方式见 `docs/历史延迟排查与后续接入.md`。这是后续多智能体可复用的工具和证据基础，尚未实现多个模型角色协作。
