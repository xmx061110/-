## 可以据此提出的业务检查

1. 类别 `beleza_saude` 的已送达商品成交额最高，为 1233131.72 BRL。可优先核查该类别库存与履约资源，但现有数据不能判断利润最高的类别。
2. 6,534 个已送达订单晚于预计送达日。应将交运代理异常与后续配送耗时分开检查，避免仅凭送达延迟处罚商家。
3. 低评分率基于有评分的已送达订单，存在评价选择偏差。未评价订单不作为好评；取消订单的客户体验需要独立专题分析。
   - 准时且有评分样本：89,420 单，低评分 8,278 单，占 9.26%。
   - 延迟且有评分样本：6,381 单，低评分 3,983 单，占 62.42%。
   上述是描述性相关，不能证明延迟造成低评分。

4. 商家比较时建议至少有 30 个相关订单，并进一步检查有效延迟/评分分母。`--min-orders 30` 仅筛选订单样本量，不构成统计显著性检验。
5. 2018-09、2018-10 处于样本尾部且状态结构特殊，不直接据此判断经营崩塌；需要新增数据确认业务趋势。

## 可直接运行的筛选示例

```powershell
python -m zhice metrics --month 2018-01
python -m zhice metrics --category beleza_saude --group-by month
python -m zhice metrics --group-by seller --min-orders 30
python -m zhice metrics --month 2017-09 --category cool_stuff --seller 48436dade18ac8b2bce089ec2a041202
```

最后一条组合筛选的真实结果见 `examples/combined-filter.json`：订单量 19，销售额 1814.00 BRL。

类别与商家筛选必须在同一商品行同时满足；只计命中商品的金额，关联订单去重。订单量和延迟/低评分人数可跨类别或商家重复出现，不能把分组结果简单相加。付款在类别/商家维度返回 NULL，避免把整单付款重复归属。
